## P01 按需采集与告警后台调度

**方案来源与落点：** §2、§8。修改 `internal/control/{control,connection,scheduler,query,services}.go`、`internal/collector/` 和相邻测试；保留现有 `/bin/sh` SSH 执行入口、队列与分项快照发布，不新增常驻采集程序。

**实施：**

1. 对当前问题记录绑定类型、目标连接版本、轮询开关、队列状态、采集尝试/成功时间、各组错误码和项目数；对照统一服务、主机网络接口与相应视图。仅收集必要、脱敏证据；连接测试通过与首轮数据采集通过是两个独立事实。
2. 增加 `POST /api/v1/collection-requests`，后端按 `view` 和目标／页签选择白名单组，尽快返回已受理的 `jobs`，不等待远程采完；无目标时返回 `200 {"jobs":[]}`。`hosts` 对当前主机绑定页请求 `host_metrics`、`os_info`，`clusters` 对当前集群绑定页请求 `nodes`、`pods`，两者均复用 `targets` 的目标筛选和分页参数；`services` 按来源／选中目标请求 `systemd` 或 `deployments`，行级筛选不发起采集；`host_metrics` 只请求给定主机的性能；`network`、`cluster` 只请求给定目标的当前分组。没有全量视图或任意组接口，不提供全量或逐机采集操作。前端通过 `GET /api/v1/jobs/{id}` 等待终态；同一查询端点仍供服务启停、授权维护等既有任务使用，操作成功后的定向刷新照旧。
3. 页面、后台告警和操作后刷新共享现有队列：跨目标异步并发，复用 SSH 最多 4、Kubernetes API 最多 2 的上限；同目标串行。同一连接版本、目标和分组的在途任务幂等复用；不同分组的待执行项可合并，同一批合并组复用连接。部分分组在途、另一部分新入队时，按 `job_id` 去重返回所需的多个 Job。解绑或改连时取消旧连接版本的工作并拒绝旧快照发布，改名不重新排任务。
4. 后台仍只采集有效告警规则所需的分组。页面以 `due_only:true` 提交，由服务端按当前连接版本的最后一次尝试和该组间隔判定。禁用定时采集时，页面还可采集没有尝试记录的组；操作后的定向刷新不受此开关影响。`GET /api/v1/collection-status` 返回本范围的到期标记、下次页面时间、后台进度与下次后台时间，不启动任务。系统采集事件不增加后台依赖。
5. 服务行继续通过 `/api/v1/services` 查询，主机来源为 `systemd`、集群来源为 `deployments`。按目标分页的 `/api/v1/targets` 补充 `summary.service_observation` 的 `group`、`observed_at`、`stale` 和 `has_items`；用 `has_items` 区分已发布零行与未观测，不拿筛选结果替代发布状态。网络独立读取 `interfaces`、`routes`、`listeners`、`firewall`。保留同连接版本的上次成功数据和观察时间，部分失败不清空其余分项；失败细节接 P07 告警，不新增单目标失败标记或控制入口。
6. 广范围服务请求每次最多受理 32 个绑定目标，按 `next_cursor` 继续，仅当前批结束且仍在原视图才续页。后台到期与在途按需冲突时按 §2 的先后关系归并，连续切页不饿死后台。只有 `target_reachable` 规则时按实际探针结果收尾。快照的新鲜度及启停可用性不随后台开关或规则有无变化；验证开关关闭后首采仍可运行，但已有尝试的分组不自动重采。

**完成判据及出口：** 用可控时钟和混合主机／集群验证请求白名单、同组在途去重、合并连接与独立并发上限；零规则时无后台作业；启用／关闭、删规则、连接换代及时收敛依赖。用两个并发目标、同主机不同页签及同列表不同分页验证 `collection-status` 的范围隔离；按需任务与当前范围到期后台任务重叠时只显示对应的状态，完成且确有安排才返回下一次采集时间。验证部分失败、写入错误收尾、发布后完成、同分组旧快照隔离、权限部分失败以及启停／授权后的定向刷新。获准后复测真实故障；未有实机证据则记录待复测，独立开发继续。

## P02 业务页面按需加载与采集设置

**方案来源与落点：** §2、§3。修改 `web/{app.js,index.html,app.css,smoke.mjs}` 中已有路由、侧栏、业务页及冒烟测试，新增一级「采集设置」页；不引入新前端框架，依赖 P01 的状态与任务契约。

**实施：** 两种入口无路由参数时均渲染「主机管理」的主机标签；侧栏依次为主机管理、服务、网络、告警、采集设置。`locationFor()` 在 Web 端保留 `/?view=services` 及相关筛选参数，在桌面端使用 `#?view=services` 等片段地址，只改变片段、不写入凭据；两端共享路由状态和视图处理。`params()` 用 `URLSearchParams.toString()` 代替 `.size` 判断是否有查询参数；内部切换继续异步。打开业务页或更换影响数据范围的目标、页签、主机绑定列表页时，先显示已有快照或待采集态，再读取采集状态；首次或间隔到期时防抖 250 毫秒后提交。前端跟踪 `job_id`，按路由、目标、分组及查询范围组成的视图标识核对结果；迟到回包只留给缓存更新，不覆盖新视图。普通关键词或服务状态筛选、排序、快照查回后重绘不会重新触发采集；离开视图取消防抖和进度轮询，不影响已入队及后台共用任务；返回同一范围时续接在途任务。

需要采集的业务页在内容区右上角预留状态位，以同一个视图范围查询 `/api/v1/collection-status`；窄窗换行后仍放在页头。当前视图有按需任务时，按去重后的 `job_id` 计进度，成功、失败和取消都计入终态；分批请求的服务视图只显示当前批次的分母，后台状态仍按完整视图范围查询。当前视图没有在途按需任务时，才显示该范围实际在跑的后台任务；都结束后，用当前范围的 `next_foreground_at`、`next_run_at` 中最早的有效时间与 `server_now` 起算倒计时。停留页面时，到期后重新校验并提交；没有计划则保持空白。后台任务结束后重读快照和到期状态。任务执行中、倒计时到点、恢复焦点和采集范围变化时重新读取状态；空闲时低频查询，离开停止查询，过期响应不覆盖下一页。一级「采集设置」只放定时采集开关、三类间隔等表单，不展示进度、不倒计时；不新增进度详情。业务页不恢复全局或单目标采集及重试按钮，只保留必要的快照观察时间和过期状态；失败通过既有告警事件查看。网络保留侧栏、主机选择、网络分项与防火墙授权，移除内容区「主机管理」。无显式 ID 时按既有顺序选择首台并用 `replaceState` 固化；显式失效 ID 不改查其他主机。

**完成判据及出口：** 两种入口都进入主机管理；最低目标 WebKit 上验证带参数路由、前进后退、默认目标的 `replaceState` 和切页无整页刷新；桌面端在三种原生 WebView 各测片段内的 `pushState`、`replaceState` 以及前进后退。检查主机列表、集群列表、服务、性能、网络和集群详情的请求分组及本地筛选不重触发；模拟旧请求迟到，确认不会覆盖数据及状态。各需采集页的进度与倒计时始终在右上角，只反映当前目标／分组／列表范围；无任务无计划时不显示，状态接口暂不可用时隐藏并重同步。采集设置仅有表单，其他页面不新增采集控制或失败弹窗；网络保留四种主机选择情形。

## P03 系统与容量用量列

**方案来源与落点：** §4。修改 `internal/collector/{collector,linux}.go`、`internal/control/{scheduler,query}.go`、`web/{app.js,app.css,smoke.mjs}` 和相邻测试；新采集组和用量字段沿现有快照保存，不为系统版本另设数据库实体。

**实施：** 在同一组 CPU 差分样本里取逻辑核数及总利用率，已用核当量为二者乘积；首次没有有效差分、主机重启或计数回退时按缺测显示。内存使用 `MemTotal - MemAvailable` 与 `MemTotal` 的字节值；磁盘在有效挂载中按 `used_bytes / total_bytes` 选择使用率最高的一项，并列时取按路径排序第一项。显示该挂载点的已用字节、总字节与对应百分比，不跨挂载相加。旧百分比字段（包括 `disk_percent`）、告警及详情页保持原语义。系统版本在主机列表实际请求该分项时，经独立 `os_info` 组读取 `os-release` 文本，优先使用 `PRETTY_NAME`；不执行文件，也不为系统版本开启独立后台轮询。读取失败仅影响系统列，不阻断主机指标。系统列和三列用量只出现在主机列表，不混到集群列表。

## P04 桌面进程内传输与共享接口

**方案来源与落点：** §5、§7。修改 `internal/httpapi/server.go`、`web/app.js`，与 P05 在计划新增的 `internal/panelruntime/`、`internal/desktop/`、`cmd/imon-desktop/` 接线，并补接口适配测试。公共业务路由不依赖浏览器会话；由各入口负责校验来源。

**实施：**

1. 将共享控制层和 HTTP handler 与监听过程分离。桌面壳从本机二进制嵌入资源提供 WebView 原生虚拟源的静态文件；不建立 TCP/HTTP 监听，不启动独立 Web 端。不通过虚拟源执行 Fetch 调用业务 API，也不建立 Cookie 会话。桌面窗直接显示主机管理，不生成激活链接。
2. 前端用同一个 API 适配器消费统一的状态码和响应内容：Web 路径由 P08 使用同源 Fetch，桌面经原生异步 JSON 桥进入进程内 Go handler。业务消息只包含 `request_id`、`method`、`path`、`body`，只允许受信顶层文档调用受支持的方法和 `/api/v1` 下的业务路由；不代理任意 URL、静态资源或会话。应答按 `request_id` 匹配，页面导航或窗口销毁后不把旧应答送给其他文档。回调提供 frame 元数据的平台用其校验顶层文档和精确来源；回调不提供该元数据时，原生仅向受控顶层注入每窗口随机凭据，桥校验该凭据，并在导航限制和资源策略中禁止 iframe、外部文档。凭据不进入业务字段、URL 或持久存储；不相信 JS 自报来源。
3. SSH 私钥选择仍由原生文件对话框实现，防火墙维护脚本按 Job ID 经共享处理器读取，使用专用原生保存对话框，桥不接受任意路径写入。桌面壳初始化或原生桥连接失败仅在桌面报告错误，不回退到 Web 服务。

```text
打开网络详情 → 原生桥调用共享 handler → 内容区异步更新
防火墙脚本 [保存] → 系统保存对话框 → 用户确认目的地
```

## P05 三平台桌面壳

**方案来源与落点：** §6、§8。从 `cmd/imon/` 抽出公共启动和释放过程到 `internal/panelruntime/`，新增 `cmd/imon-desktop/`、`internal/desktop/` 及 `packaging/desktop/`；复用嵌入前端、进程内业务处理器和数据目录。通过 cgo 接入固定的上游 WebView v0.12.0 C API；macOS 13+（amd64/arm64）用 WKWebView，Ubuntu 24.04（amd64）用 GTK3/WebKitGTK 4.1，Windows 11（amd64）用 Evergreen WebView2；不新增内嵌 Chromium 或复制采集核心。

**实施：**

1. 先用选定的 WebView C API 在各平台启动最小窗口，确认静态资源虚拟源、顶层来源校验、原生异步桥、JS/CSS 基础支持、窗口主线程、文件选择与保存、构建分发与退出。固定依赖版本，CGO 与图形工具链只用于桌面构建；独立 Web 入口由 P08 维护，不是桌面组件。
2. 初始化运行时并接好 P04 的静态加载与桥接后打开窗口，默认主机管理；不调用网络监听。同目录由现有锁防止两个实例写入；关闭窗口后停止运行时并释放锁。macOS 给固定版 WebView 的 Cocoa 后端加最小补丁，在构造 WKWebView 前向配置注册 `WKURLSchemeHandler`；Linux 在导航前用 `webkit_web_context_register_uri_scheme`；Windows 在导航前用 `WebResourceRequested` 拦截应用专用 `.invalid` HTTPS 主机并返回嵌入资源，不映射本地文件夹、不允许缺失路径落入真实网络请求。通过上游原生句柄接入导航钩子：业务页仅载入本源，用户点击的 HTTPS 外链交给系统浏览器，其他外部导航和弹窗不留在应用窗口。不把原生权限暴露给外部页面。
3. macOS 分架构打包 `.app` 到 `.zip`；Ubuntu 构建 `amd64` `.deb`，声明运行时与 `zenity` 文件选择依赖；Windows 产出每用户安装的 `amd64` `.exe` 候选包，使用 NSIS。运行时缺失或桌面窗口初始化失败给出明确报错与缺失依赖，不提供 Web 界面。OS 图形会话或测试机未具备时仅将对应平台标为待验证，不将构建通过替代真实启动。

**完成判据及出口：** 按方案的平台矩阵在每一支持架构记录产物、启动截图、功能操作、运行中无 Web 监听、退出后锁状态和缺依赖提示。至少覆盖打开、导航、原生文件选择／保存／取消、关闭重开、外链与已有同数据目录实例；窗口驱动的自动或人工验证均保留证据。任一平台阻塞时保留依赖、工具链、初始化或导航的验证证据，按 §6 处理，不以独立 Web 版验收代替该平台验证。P01–P04、P07 和 P08 的独立工作继续。

## P07 采集失败告警与性能对照

**方案来源与落点：** §2、§8、§9。修改 `internal/control/scheduler.go`、`internal/alert/{engine,http,model,notify}.go` 与 `web/app.js`，补相邻测试；沿用现有告警事件、已读状态、通知设置与投递队列。

**实施：** 针对当前连接版本的采集分项终态自动生成 `collection` 来源告警。用目标、连接版本和分组合成稳定的系统 `rule_id`，复用既有事件的活动唯一约束，不向用户规则表插入记录。同一分组采集失败重复发生时更新已有活动事件，不重复送达；分组观察真正成功后恢复，解绑或改绑时结束旧事件，不标为恢复。连接失败只形成 `probe` 事件，未执行的各组不再各发同一故障。已预期的未授权防火墙读取不当作故障，原有权限失效仍发告警；取消不发失败告警。事件和外发入队同事务；面板通知开关只控制未读提示，Telegram、邮件仅发往已开启并配置的接收目标。用户始终可以在现有「告警 → 事件」列表及详情查看故障；「采集设置」不另做失败列表。系统采集事件本身不产生后台采集依赖。

在等价目标、同等分项输出和缓存条件下，对照「按需／同目标合并并复用连接」与「连接复用、每目标各组串行全量」。用合成延迟和输出夹具分别覆盖单主机正常延迟、高延迟、非所需分项大输出、所需分项大输出及多主机场景；首条新数据可见时间和全部实际请求完成时间分开统计，同时记录执行次数、连接数、接收字节、中心端 CPU 时间与峰值内存和达成的并发数。重复测量，分别记冷／暖快照结果；避免把缓存命中或额外开连接变成对照差异。高延迟、多主机与大输出的生产数据需要获准实测，不预设提升比例，也不把模拟结果当现场结果。

## P08 独立 Web 入口与浏览器会话

**方案来源与落点：** §5–§8。复用 `cmd/imon/`，修改启动参数、`internal/httpapi/server.go` 的入口会话与 `web/app.js` 的启动接线；更新 `packaging/release/smoke.py` 和 `web/smoke.mjs` 中仍按一次性链接启动的夹具。P04 提供共享 handler；此项不接桌面壳、不变更业务接口。

**实施：**

1. 现有 Web 入口的默认端口由随机分配改为 `8765`，只在 `127.0.0.1` 监听；`--port` 可指定有效的正整数端口。端口占用时报告冲突并提示显式改端口，不随机换址。应用启动后输出普通可重复打开的本机地址；默认进入「主机管理」。浏览器刷新、开新标签和应用重启后均可继续用同一地址。
2. 静态入口只提供面板资源；同源的 `POST /api/v1/session` 使用空对象创建本进程的浏览器会话，返回按端口命名、不带 Domain 和持久化属性的 `HttpOnly; SameSite=Strict; Path=/api/v1` Cookie。前端复用有效会话，服务重启后重新建立会话，不用 URL 密钥或激活页。除会话建立外，业务 API 仍要求有效会话。检查回环对端和精确 Host；会话建立及写操作要求精确同源 Origin；请求有 Fetch Metadata 时 API 只接受同源请求，禁用 CORS 和外站嵌入。首版以本地使用为范围，不提供局域网、公网和多人共用。
3. 保留现有数据目录锁、退出释放、本机私钥选择与路径输入、防火墙脚本浏览器下载及独立备份恢复；不在 Web 包里启动或夹带桌面壳。端口绑定、会话初始化失败时报告本地启动问题，不改用旧激活 URL。
