# 02 · Imon 0.1.0 技术方案

对应 [02 开发计划](../plans/02-v0.1.0-desktop-and-collection.md)、[发布功能清单](../guides/v1-features.md)和[界面草图](../design/v1-ui-wireframes.md)。本文是 0.1.0 拟实施契约，覆盖 [01 技术方案](01-v1-technical-solution.md) 中相冲突的交付形态、会话、轮询、手动采集和版本说明；历史构建与验证记录保留。示例是目标行为，不代表实机结果。

## 1. 范围与组件

| 需求 | 0.1.0 行为 | 对应任务 |
| --- | --- | --- |
| 服务、网络无内容 | 进入业务页面按需采集并发布快照；采集失败进入现有告警事件 | P01、P07 |
| 并发异步与后台采集 | 不同主机并发，同目标分组串行；后台只采集启用且有效的告警规则所需分组 | P01、P02 |
| 页头采集状态 | 各采集页面在右上角显示本视图进度或下一次采集倒计时；一级「采集设置」只管理开关和间隔 | P01、P02 |
| 主机管理置顶、默认打开 | 根路径显示主机管理；保留异步切换和显式深链接 | P02 |
| 显示系统、容量和用量 | 主机列表显示系统版本与 CPU／内存／磁盘的已用量、总量和百分比 | P03 |
| 精简网络工具栏 | 移除「主机管理」和逐主机采集按钮，保留主机选择、页签和授权入口 | P02 |
| 取消启动链接口令 | 桌面直接打开窗口；独立 Web 版使用可反复访问的普通本机地址 | P04、P08 |
| 版本 0.1.0 | 桌面窗口、应用元数据和安装包使用同一版本来源 | P06 |
| 独立桌面与 Web | 同版本交付两种独立入口；启动桌面版不会同时启动 Web 服务 | P04、P05、P06、P08 |

两端共用 `web/`、Go 业务路由、队列和 SQLite。桌面链路为「WebView → 原生桥接 → 进程内 Go Handler」；Web 链路为「浏览器 → 独立 Web 程序的本机 HTTP 监听 → 同一 Go Handler」。模式随入口确定，不互相启动或自动切换。相同数据目录仍只允许一个实例，切换时先退出原实例；桌面不监听 HTTP，不影响 SSH、Kubernetes 或通知的出站连接。Kubernetes 不限于 K3s；远程宿主机仍为 Linux + systemd，SSH 指纹确认、辅助程序和防火墙授权模型不变。保留三类后台周期，不增加绑定数量上限，不提供全局或逐目标的全量采集入口。

## 2. 首次采集、快照与数据状态

**已从源码确认：** `internal/control/connection.go` 保存绑定后唤醒调度器，不在保存请求中采集；定时轮询关闭时不会自动发起远端采集。`internal/control/services.go` 的服务查询只返回已发布的 systemd 和 Deployment 行，目前空列表不足以区分无匹配、未采集和采集失败。网络查询已有分组尝试／快照信息；`web/app.js` 在没有主机参数时不会自动取首台主机的数据。以上是复现和排查入口，**不是已确认的实机根因**；SSH 连接测试或 shell 探针通过不等于数据已写入快照。

**页面触发：** 进入业务视图先读当前连接版本的快照。每个目标的每个分组在当前连接版本没有尝试记录时可立即首采；已有记录时，按对应主机、网络或集群间隔从上次尝试结束计时（含失败）。在页面停留到期或到期后重返，才再次请求该组。关闭定时采集仍允许首采，不自动重采已有记录。目标、绑定分页或资源页签切换会换采集范围；名称、状态、命名空间筛选和数据行分页只读快照。前端提交前防抖 250 毫秒；离页撤销未提交的请求和页面轮询，已受理的任务不撤销，返回可续用。旧响应不重绘新页，解绑或改绑时旧连接结果不会发布到当前连接版本。首次或基线失效的页面指标采样复用现有有界双采样；无有效差分时显示缺测。

| 请求视图 `view` | 后端推导的目标与分组 |
| --- | --- |
| `hosts` 主机列表 | 当前绑定列表分页的 Linux 主机：`host_metrics`、`os_info` |
| `clusters` 集群列表 | 当前绑定列表分页的 Kubernetes 集群：`nodes`、`pods`，供摘要就绪数与异常数使用 |
| `services` 服务 | 按来源和目标范围取宿主机 `systemd` 或集群 `deployments`；未筛选时涵盖两种来源，不取集群 `services` |
| `host_metrics` 机器性能 | 当前 Linux 主机的 `host_metrics` |
| `network` 网络 | 当前 Linux 主机和当前页签：`interfaces`、`routes`、`listeners`、`firewall` 四选一 |
| `cluster` 集群详情 | 当前集群和当前资源页签：`namespaces`、`deployments`、`pods`、`services`、`nodes` 五选一 |

**并发与归并：** 继续使用 `internal/control/scheduler.go` 的队列、派发和分组发布。初始上限沿用 SSH 4、Kubernetes 2，按不同目标并发；同一绑定目标同一时刻只执行一个采集任务，其所需分组串行复用已经打开的连接。所有触发来源用 `(target_id, connection_rev, group)` 合并等待和在途工作，独立分组不因同一连接被顺带读取。页面可加入已排定的后台分组；若后台到期且同组按需工作尚未开始，合并为定时任务；若已开始，等它结束后先安排到期样本，不把非定时样本补记为定时样本。服务页各目标有结果即可增量重读，不等所有目标完成。启停、授权后的定向刷新仍走同一调度约束，但不制造后台订阅或额外一轮采集。

**后台资格：** `plan` 只读已启用且通过现有指标、目标类型与选择器校验的规则，按目标和依赖分组合并。`internal/alert/model.go` 的指标映射为单一来源：告警 `metrics` 对应采集的 `host_metrics`；systemd、监听、节点、Deployment、Pod 对应其自身分组；`target_reachable` 只做连接探针。探针随同批数据采集复用，不单独重复连接；若本次只有探针任务，按实际探针结果判定终态，不以分组结果为空判定成功。无需先有成功快照、也不因暂时不可达或对象不在当前快照而取消有效规则；系统生成的采集异常事件不是规则，不会开启或扩大后台采集。没有合格规则的目标后台不连接。连续次数或持续时间只使用符合当前规则和调度代际的定时样本，不让频繁切页加速触发。保留原有三类周期：主机性能与服务、网络、集群。

**后台轮次：** 仅有到期工作时启动，固定当轮目标及到期分组；一轮尚未结束不新增重叠后台轮。每个目标在本轮所有组发布或判定后计一次，`completed = success + partial + failed + canceled`；持久化失败也有终态。规则、绑定、连接版本、后台开关或周期变化后重新计算；已移除资格的未执行分组取消，旧任务仍按超时收尾、不得作用于已失效规则。退出重启后按当前有效规则重建，无历史补采。空闲时 `next_run_at` 为各合格分组的最早可执行时间（到期与退避取较晚者）；没有计划或关闭时不倒计时。

**接口：** `POST /api/v1/collection-requests` 接受上表的视图和适用参数。页面提交 `{"view":"network","target_id":"<TARGET_ID>","group":"listeners","due_only":true}`，服务端只入队仍到期的分组并复用覆盖范围内已登记的任务；有任务返回 `202 {"jobs":[{"target_id":"<TARGET_ID>","job_id":"<JOB_ID>"}]}`，无任务返回 `200 {"jobs":[]}`。省略 `due_only` 时保留已有显式采集接口行为。同一目标部分组在途时可返回多个 Job，客户端按 `job_id` 去重。`hosts`、`clusters` 复用各自绑定筛选与分页参数；`services` 可传 `source`、`target_id`；详情指定不存在的目标返回 `404`，组与类型不匹配返回 `400`。保留 `GET /api/v1/jobs/{id}` 追踪本视图任务及既有启停、授权任务。

`GET /api/v1/collection-status?view=network&target_id=<TARGET_ID>&group=listeners` 只读当前视图状态（服务页以完整来源／目标范围计算）。返回 `server_now`、`foreground_due`、最早未来页面到期时间 `next_foreground_at`、后台 `next_run_at`（时间均为 Unix 毫秒或 `null`）、相关后台进度 `active`（`{total,completed}` 或 `null`）。一个目标的所有匹配分组都到终态才计为完成。页面空闲时用最早的未来时间显示倒计时；没有下次时间则留空。后台任务结束后重读快照和状态，到期判断以服务端为准。

宽范围的 `services` 请求最多受理 32 个绑定目标，沿既有稳定的绑定游标顺序选择；还有候选时响应附 `next_cursor`，客户端保持 `view`、`source`、`target_id` 不变并传入 `cursor`。同一视图当前批结束才自动继续下一批；离开视图不提交续页，不撤销已受理或被后台共享的工作。单组快照仍是完整分组，集群命名空间筛选、表格数据分页不发布半份快照，也不重新采集。

**来源：** 统一服务仍展示宿主机 systemd 单元与集群 Deployment；Kubernetes Service 对象仍显示在集群详情，不因统一列表重构改变对象语义。网络分组为 `interfaces`、`routes`、`listeners`、`firewall`，每组独立尝试和发布。`permission_denied` 等防火墙错误只影响该页签，其他组成功后正常显示。保留 `/bin/sh` 的 SSH 命令入口和已有授权约束。

**查询：** 网络沿用 `GET /api/v1/hosts/{id}/network/{group}` 的 `items`、`attempt`、`observed_at`、`stale` 和分页。`GET /api/v1/services` 保持服务行与分页契约；在分页 `GET /api/v1/targets` 的每个目标 `summary` 内增加 `service_observation`，含 `group`、`observed_at`、`stale` 和 `has_items`。`observed_at` 是最后成功发布时间；`has_items` 用同版本已发布批次做 `EXISTS` 判定，无成功批次为 `null`。服务名称、状态和命名空间筛选只作用于数据行，不改变成功空结果的判断。已有快照可继续查阅，不显示逐组进度、采集失败提示条或重试按钮；采集异常详见 §9。界面本身的读取请求失败仍显示读失败，不伪造成功空数据。

| 观测状态 | 页面表现 |
| --- | --- |
| 无成功结果 | 显示「暂无已采集数据」，不判断为无服务或无网络对象 |
| 排队／运行 | 保留现有快照或未采集状态；本视图右上角显示对应采集进度 |
| 最近成功且有行 | 显示结果与观察时间；筛选后零行提示「未找到匹配项」 |
| 最近成功且组内零行 | 显示「采集成功，未发现数据」及观察时间 |
| 最近失败或结果已过期且有成功快照 | 保留上次成功的数据或空结果，标记时间和过期；失败内容只出现在告警 |

`internal/control/query.go` 的快照新鲜度按最后成功时间、尝试结果及现有分组时效（两倍配置周期）判断，不依赖后台开关或是否配置规则。服务列表首次按需结果发布后重算启停按钮状态；保留对过期快照的操作保护，不再提示点击已移除的手动采集按钮。

**排查路径：** 在当前面板或同类测试目标记录轮询状态、连接版本、Job 状态与分组错误 → 区分 SSH/API 连接、命令或权限、解析、SQLite 发布、前端请求与渲染 → 修复最先失败的环节 → 对同一目标复测。`read_failed` 要核对发生阶段，不能仅凭错误码断定远程命令失败。网络首先验证接口、路由、监听；已有权限时再验证防火墙。复现证据只记录脱敏版本、时间和错误类别；观察不到现场时按 §8 处理。

## 3. 默认路由、采集设置与网络工具栏

- `web/index.html` 侧栏依次为「主机管理、服务、网络、告警、采集设置」；版本号留在左下角，不新增「版本管理」栏目。两端默认打开主机管理的「主机」页签，使用相同的路由状态和视图逻辑。Web 保留 `/?view=targets`、`tab=clusters`、`/?view=services` 和既有详情深链接；无 `view` 但含 `source`、`target`、`state`、`namespace` 或 `q` 的历史服务筛选链接继续可解析。桌面将同样的路由参数编码到 `#?view=services` 等片段中，只在原生虚拟地址上更新片段，不改协议、主机、路径或查询；片段不存凭据。`params()` 以 `query.toString()` 是否为空拼接问号。两端支持异步切换、前进后退，以及用 `replaceState` 固化默认目标，不刷新整个页面。
- `view=settings` 仍是一级「采集设置」，只提供后台开关、三类周期及原连接超时表单。主机与集群列表、服务、机器性能、网络、集群详情在页头右上角使用同一状态槽；以当前分页、目标及采集分组为范围，窄窗口可在页头换行并保持右对齐。优先显示页面触发的任务进度（按当前批去重后的 Job 统计，失败与取消也计作完成），其次显示该范围正在运行的后台进度，最后在存在实际后台计划时显示倒计时；三者互斥。服务页分批采集时标示「本批」，不将当前批任务数冒充全页总数。
- 状态不可用或无实际计划时留空。倒计时按 `next_run_at − server_now` 本地递减；有活动任务、到期、恢复焦点或切换采集范围时异步重读，空闲时以低频更新发现规则变更。后台当前范围的任务完成后重读对应快照，不重新触发前台采集。退出视图时停止本视图状态查询，旧响应不得覆盖新视图。不增加运行页、失败弹窗、全量或逐目标采集按钮；失败仍进入「告警 → 事件」。
- 网络有显式有效主机 ID 时保持选择；未指定时选主机列表中的首个 Linux 目标，并用 `replaceState` 固化选择。无绑定显示空态；显式 ID 不存在或已解绑时提示并显示主机选择，不转查其他目标。移除「主机管理」以及服务、网络、机器性能、主机行、集群详情中的逐目标采集／重试按钮，保留侧栏、已有返回语义、主机选择、网络页签及防火墙授权入口。

## 4. 主机列表指标口径

沿用 `internal/collector/linux.go`、`internal/control/{scheduler,query}.go` 的采集与发布链路。在对应快照行添加字段，旧批次缺字段时为缺测；不把 `0` 当成缺测，不因新增字段全量重采数据库。将 `os_info` 注册为主机列表的按需分组，过期展示参考主机周期；没有告警依赖，不进后台计划。

| 列 | 输入与算法 | 例子 |
| --- | --- | --- |
| 系统 | 新增独立轻量 `os_info` 组：优先读 `/etc/os-release`，仅不存在时回退 `/usr/lib/os-release`；解析文本键值、引号和转义，不执行。依次取 `PRETTY_NAME`、`NAME` 加 `VERSION` 或 `VERSION_ID`、`ID` 加 `VERSION_ID`，无有效项显示 `—`。读取长度有界，失败只影响本列。 | `Debian 12` |
| CPU | 同一次 `/proc/stat` 读取聚合行和各 `cpuN` 行；在现有差分基线里记录逻辑核 ID 集。按现有利用率口径折算 `已用逻辑核当量 = 利用率 × 在线逻辑核数`。首次无有效差分、重启、计数回退、采样间隔无效或核集合变化时显示 `—`，基线更新后再显示。 | `2.0 / 8 核 (25%)` |
| 内存 | `/proc/meminfo` 中 `已用 = MemTotal − MemAvailable`，已用和总量用字节存储；百分比用同一对数值计算。缺字段或数值越界显示缺测。 | `8 / 16 GiB (50%)` |
| 磁盘 | 沿用采集组对挂载点和虚拟文件系统的过滤，从有效行中按 `used_bytes / total_bytes` 选最高者，并列按挂载点字符串升序第一项；分子、分母与百分比都取同一挂载点，不累加，不显示为整机磁盘总容量。提示中展示挂载点。 | `40 / 100 GiB (40%)`；挂载点 `/data` |

磁盘新列百分比按已用／总量计算，有预留块时可能与 `df` 利用率、现有磁盘告警与详情页比例不同。旧 `summary.cpu_percent`、`memory_percent`、`disk_percent`、历史序列和告警判断保持原语义。`host_metrics` 若受网卡命令失败影响，定位到组内子命令，不误报权限；需要时隔离可失败的网络子采样，已取得的 CPU/内存/磁盘有可验证数据才发布，不制造零值。

`GET /api/v1/targets?kind=host` 追加 `summary.host_usage`：`observed_at` 为批次观察时间，`cpu` 含 `used_cores,total_cores,percent`，`memory` 含 `used_bytes,total_bytes,percent`，`disk` 含 `used_bytes,total_bytes,percent,mountpoint`；子项缺测为 `null`。`summary.os_info` 为 `{display_name,observed_at,stale}` 或 `null`。展示单位统一使用 IEC 存储单位与逻辑核数；只在最终渲染四舍五入，用量与容量尽量使用同一单位。集合旧值沿用观察时间，不将标为过期的数据冒充实时用量。以上新列不进入集群列表。

## 5. 桌面与 Web 启动

**共享运行时（P04）：** 在 `internal/panelruntime/` 统一打开数据目录、初始化路由和启动调度器，关闭时释放资源。拆分 `internal/httpapi/` 中的业务 Handler 和浏览器会话中间件；业务 Handler 保持 `/api/v1` 路径及状态码，不依赖 Host、Origin 或 Cookie。Web 接入中间件后才向网络提供 Handler；桌面只从进程内桥调它。`web/app.js` 的 API 适配器在 Web 用同源 `fetch`，在桌面用原生桥；保留统一的成功／错误结构和同一跳转逻辑。两端只读当前实例的数据，不共享浏览器会话。

**桌面入口（P04、P05）：** 原生壳加载本地打包资源，不创建 TCP／HTTP 监听器、不打印链接。状态管理和采集在同一进程中运行。原生桥只在受控顶层文档中暴露，调用形状为 `{"request_id":"<REQUEST_ID>","method":"GET","path":"/api/v1/targets?kind=host"}`，写入操作可附 JSON `body`；返回 `request_id`、`status` 和 `body`。桥验证方法、路径和请求大小；路径仅允许应用业务 API 下的规范相对路径，拒绝绝对 URL、路径穿越及浏览器会话端点，不能执行任意命令或请求外部地址。Go 通过进程内 request／response 包装调用 Handler，远程采集不阻塞 GUI 线程；窗口关闭时取消未完成的桥调用。校验消息的精确本地来源和顶层 frame；平台桥缺少所需 frame 身份时，在原生注入的顶层闭包内使用每窗口随机证明，桥必须验证该证明，同时禁止嵌入与外部导航。桌面初始化失败显示窗口错误，不启动 Web 服务。

**Web 入口（P08）：** 复用 `cmd/imon/`，默认 `127.0.0.1:8765`，支持 `--port` 指定非零端口；占用时明确退出，不静默改端口。启动只输出普通本机地址，不含 token 或 fragment。稳定地址可反复打开、刷新或在服务重启后重用；`GET /` 提供静态入口，页面对精确同源发出 `POST /api/v1/session`，请求体 `{}`，返回 `204` 并签发按端口命名的 host-only Cookie（`Path=/api/v1; HttpOnly; SameSite=Strict`，不持久化）。同进程已有有效 Cookie 时复用；重启使旧 Cookie 失效，页面重新建会话，无需重启服务或取新链接。业务 API 需有效 Cookie；检查回环对端及精确 Host，写请求及会话建立校验非空精确 Origin，所有 API 在存在 Fetch Metadata 时只接受同源；不开放 CORS 或嵌入。此首版为本机单用户，不做局域网监听、公网部署或多用户登录；拥有本机访问权限的进程不在此会话机制的隔离范围内。

**文件操作：** 两端继续使用运行主机的私钥路径或本机文件选择，不上传私钥。Web 版浏览器保留现有本机选择接口及防火墙脚本下载；无图形选择器时允许输入本机绝对路径。桌面沿用原生选择，脚本保存走专用原生保存对话框，由 Job ID 取共享业务路由的脚本内容，不增加按任意路径读写文件的桥方法。

## 6. 桌面封装与交付矩阵

桌面入口使用固定版本 `webview/webview` v0.12.0 的 C API（cgo），新增 `cmd/imon-desktop/`、`internal/desktop/` 与 `packaging/desktop/`。Web 版仍从 `cmd/imon/` 独立构建，复用现有无图形依赖的构建链，不引入 WebView。两个发行物名称区分 `desktop` 和 `web`；现有 `backup`、`restore` 仍是不启动窗口或服务的本地维护操作。上游依赖和许可随桌面产物记录，支持范围以实测结果为准。

| 首批目标（待实机验证） | 平台运行时 | 本地候选包 |
| --- | --- | --- |
| macOS 13+，amd64、arm64 | 系统 WKWebView，原生构建工具链 | 两种架构各自 `.app` 的 `.zip` |
| Ubuntu 24.04，amd64 | GTK3、WebKitGTK 4.1，`zenity` 支持现有文件选择 | `.deb`，声明运行依赖 |
| Windows 11，amd64 | Evergreen WebView2；安装时检测，缺失时提示安装 | NSIS 每用户 `.exe` 安装程序 |
| 独立 Web | macOS、Linux、Windows，均按现有 amd64、arm64 构建矩阵；无需桌面端依赖 | Windows `.zip`，macOS、Linux `.tar.gz`，逐目标验证 |

入口在主线程创建窗口；先持有数据目录锁、启动共享运行时，再注册本地资源映射和桥后导航。macOS 经 `WKURLSchemeHandler` 为应用专用 scheme 返回嵌入资源，用受版本控制的小型 Cocoa 后端补丁在创建 `WKWebView` 前将处理器装入配置；Linux 在导航前用 `webkit_web_context_register_uri_scheme` 注册应用专用 scheme；Windows 用 WebView2 `WebResourceRequested` 拦截专用 `.invalid` 虚拟 HTTPS 主机名并在进程内返回资源，未知路径直接返回错误，不落入真实网络请求。只映射打包的静态资源并设置正确 MIME；历史路由用精确协议、主机与路径判定，不依赖自定义 scheme 的 `location.origin` 或 `fetch`。Windows 虚拟来源不是开放地址。窗口只承载应用本地资源；用户点击的 HTTPS 外链才交系统浏览器。窗口关闭或初始化失败时释放调度器、数据库及锁；已有同数据目录的实例时提示并退出。桌面依赖缺失时指出缺项，不自动启动 Web 版。

v0.12.0 的 C API 没有统一的导航拦截回调。外壳通过 `webview_get_native_handle` 接平台钩子：macOS 使用 `WKNavigationDelegate` 和 `WKUIDelegate`；Linux 使用 WebKitGTK 的 `decide-policy`（含新窗口动作）；Windows 注册 WebView2 的 `NavigationStarting` 和 `NewWindowRequested`。接管时保留框架已有回调，关闭时解绑；前端点击拦截只负责交互，不作为唯一导航校验。

P05 先在三平台验证窗口主线程、静态资源加载、导航与历史、桥 GET／POST、选择／取消以及脚本保存、外链受控、无监听端口和关闭释放锁，再实测候选包。若某平台在已定工具链／运行时仍无法达成闭环，记录阻塞项并验证平台适配；涉及更换依赖或最低支持范围再确认，不以启动 Web 服务实现桌面。未验证的 Linux 发行版、桌面 Windows arm64 和公开签名分发能力不写成已支持；已有 CLI 归档不是新版桌面或 Web 的验收证据。

## 7. 版本与更新

- 构建流程以 `v0.1.0` 注入桌面／Web 程序和侧栏，桌面安装元数据按平台使用 `0.1.0`。不改变 SemVer 比较、不从此前调试构建 `v1.0.0` 自动降级。替换现有调试程序前先验证备份／恢复，失败保留旧程序和备份。
- 两种候选复用 `packaging/release/build.sh` 的临时源码树及防火墙助手装配逻辑，各自嵌入 Linux amd64、arm64 助手。桌面包不包含 Web 入口，Web 包不包含桌面程序；分别检查启动、版本及两种远端架构脚本生成。
- 当前仅本地调试：不配置公开 GitHub 仓库、不开启网络更新。版本气泡显示「未配置更新仓库」，无红点。未来配置仓库后，按桌面／Web、系统及架构匹配 GitHub Releases 资产，每进程首次打开界面时检查一次；显示红点、说明和链接，校验下载摘要，不执行 `git pull`。相应模式的替换、重启和失败恢复经验证后才启用自动「更新」，不跨模式安装资产。

## 8. 开发与验证边界

**单机全量评估（源码推算，非实测）：** 一次建连后串行取多个组，并不必然造成 CPU 峰值；如果确实需要全部数据，可以摊薄 SSH 建连与身份验证的成本。但当前 `internal/collector/linux.go` 的六个宿主机分组都成功且指标不需补采样时，按控制流会发起 `12 + N` 次远程执行（`N` 为每 64 个 systemd 单元所需的一批 `show`；不含探针和拟新增的 `os_info`）。例如，仅打开端口监听页签只需现有 `ss` 的 4 次调用。`internal/collector/ssh.go` 复用已认证的 SSH 连接，但每次远程执行仍开启独立会话。全量常见额外成本是网络往返、远端命令、数据传输及中心端的解析与写入；高延迟和大量服务、监听端口或防火墙规则会放大这些成本。若所需组排在大组后面，页面首条新数据也会延迟；在同一主机并发所有组则会叠加远端及中心端峰值。Kubernetes 大列表还需多页读取，按资源分组隔离。

**首版选择：** 默认按需，多个主机同时做各自所需的工作；同目标有两个或更多已请求分组时可串行合并并复用连接，不读取无关组。P07 在同一连接复用条件下对照按需与串行全量，分别记录首条可用新数据和任务收尾的耗时、远端执行和连接次数、传输字节、中心端 CPU／内存。至少覆盖快照冷／暖、常规／高延迟、所需／非所需组大输出及多主机；确认无关命令未执行、去重有效且并发不越界后保留该路线。若单组或整页仍慢，依据实测定位往返、输出、解析或写入，再缩小该组开销或调整并发，不直接切为默认全量。

| 未知项 | 验证及继续条件 | 失败后处理 |
| --- | --- | --- |
| 服务、网络现场无内容的根因（P01） | 对获准目标走完任务与分项发布闭环，通过后核对服务与网络显示；断言未采集、失败、真实空可区分 | 定位失败阶段，只调整受影响环节；现场不可用时保留待复测，合成回归不替代现场结论 |
| 真实目标的采集开销（P07） | 按上述口径留存脱敏对照；检查无关组不执行、同组不重复、跨目标运行不超限 | 若远端不可用，保留合成证据及待实测项；不声明生产性能数值 |
| 桌面桥、文件选择与保存（P04、P05） | 各平台实开应用；验证受控顶层能发请求，外站／嵌入不能调用；启动和退出均无产品 HTTP 监听 | 修相应平台适配；不在桌面版增加网络监听 |
| Web 稳定访问与会话（P08） | 启动后同地址打开、刷新、新标签及重启重开；回归非同源写、外部监听不可达、端口占用及同目录实例互斥 | 只修 Web 入口和会话层；不重新依赖一次性链接 |
| 桌面原生包与最低支持矩阵（P05、P06） | 对每个目标架构在图形环境实装，查验打开／导航／关闭、缺依赖提示和产物清单 | 可继续其他桌面平台；阻塞平台标待验证，确需改路线再确认 |
| 旧数据兼容与本地切换（P06） | 使用合成历史库，验证备份、启动后数据与切换失败时恢复；核对版本与外部请求关闭 | 保留旧调试产物和备份，未通过不替换原程序，不自动发布 |

执行顺序：P01 现场只读观察与 P05 最小窗口试验并行。P01 先定调度与接口，P02 再接页面；P07 可先用合成数据验证告警，待 P01 和 P02 接通后执行性能对照。P03 随 P01 验证采集。P04 交付共享运行时和桌面桥协议；P05、P08 分别完成运行联调，P06 汇总两种候选产物。未验证的原生适配不阻塞 Web 入口及共用界面的开发。

## 9. 采集失败告警

- 页面按需、告警后台和操作后定向刷新产生的已判定失败复用现有「告警 → 事件」列表、详情和投递记录，不新增独立采集页面或失败列表。每个目标的连接／探针根失败只生成 `probe` 异常，不把同次被阻断的分组各报一次；连接正常时按实际失败组告警。超时、命令、权限回归、解析和发布失败保留脱敏类别；首次未配置防火墙读取授权是能力状态，不作为故障。解绑、改绑或关闭自动造成的取消不触发异常。若该组无有效用户规则，不因事件活动而定时重试，等下一次按需或定向刷新才重新观察。
- 在 `internal/alert/` 增加采集异常观察入口，使用 `alert_events`，事件 API `source: "collection"`；为 `(target_id, connection_rev, group)` 构造固定命名空间的内部 `rule_id`，利用现有活跃事件唯一索引，不在可编辑规则列表创建条目。首次失败创建事件；同键仍失败只更新最后观测和类别；下一次该组成功发布（含空结果）、或探针成功时恢复对应事件。解绑／连接版本变化终止旧事件，不将其标为恢复。详情列目标、断点、首次与最后时间、处理状态及投递记录，不存原始远程输出或凭据。
- 事件与通知入队同事务、复用现有派发去重。事件始终可在告警中查询；面板开关只控制未读提醒。Telegram、邮件只向各自启用且已配置的接收目标投递，不打开未启用渠道；同一事件的重复异常不再次派发。底层发布存储暂不可用时，轮次仍到终态，保留有界的待记录结果并在存储恢复后幂等重试；不因未成功写入而宣称已通知。退出时只保证已持久化事件和投递可恢复。
