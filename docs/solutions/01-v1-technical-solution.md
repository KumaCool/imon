## 1. 运行方式和架构

**中心端就是本地客户端进程。** 采用 Go 单程序，以 `go:embed` 内嵌 HTML/CSS/JavaScript 面板，使用 `modernc.org/sqlite` 读写本地 SQLite。V1 以 Linux、macOS、Windows 命令行构建为交付目标，各平台通过启动、采集、保存和重启验证后才标为支持；不要求单独的桌面壳。浏览器只提供界面，不承担 SSH 或 Kubernetes 客户端职责。不部署独立服务器、数据库、消息队列或常驻主机 Agent。被监控的主机和 Kubernetes API 必须可达；防火墙辅助程序仅按需安装和执行。

| 模块 | 职责与边界 |
| --- | --- |
| 本地 Web 和 API | 读取数据库，管理连接、设置、规则和通知，提交采集、启停或维护任务，不让浏览器直接访问远端 |
| 调度与采集 | 复用到期采集批次，按目标执行 SSH 或 Kubernetes API 请求，归一化结果和错误 |
| 防火墙维护 | 按操作者发起的独立任务安装或卸载读取器；普通周期采集永远不进入维护路径 |
| 服务启停 | 使用单独配置的操作授权，执行精确目标的启动或停止并核验结果；不与允许列表外的服务交互 |
| 存储与告警 | SQLite 写入快照、历史和事件，同一事务生成面板通知和外部投递记录 |
| 投递 | 在数据库事务外从本机发送 Telegram 或 SMTP；外部渠道失败不回滚事件 |

- 默认在 `127.0.0.1` 选择空闲端口，不对局域网监听。启动口令由系统随机数生成，经浏览器 URL 片段传递，前端兑换同源 HttpOnly 会话后清除片段；口令短期有效且不可复用。API 校验会话和当前本地 Host，写请求另校验 Origin，不开放跨域。应用状态放在系统用户应用数据目录，POSIX 权限 0700/0600，Windows 使用当前用户私有目录及 ACL；同一数据目录只允许一个进程写入。
- 有界工作池和本地 SQLite 不限制绑定数量。目标能否按时采完取决于部署机器、网络和远端规模；容量不足时显示排队和延迟，不拒绝新增绑定，也不伪造按时完成。
- **本地进程退出、客户端关机或休眠期间，采集、告警计算和通知暂停。** 恢复后重新观察，只重试已入库的待投递通知，不追补未观察到的故障。若将来要求关机期间继续监控，同一程序须运行在可达目标的常开设备；连接器无需因此改为 Agent。

## 2. 连接与身份

| 目标 | 连接配置与校验 |
| --- | --- |
| Linux 主机 | 地址、端口、登录用户名、SSH 私钥路径；用 Go SSH 客户端直连或配置一个跳板。登录前核验服务器身份，跳板和目标分别校验；绑定成功需要认证及固定只读探测命令成功。表单不要求填写服务器公钥。 |
| Kubernetes | 选择本机可信 kubeconfig 和 Context；用 `client-go` 访问 HTTPS API，校验证书，不接受跳过 TLS 校验。支持客户端证书及令牌（含可轮换的令牌文件）。本机登录插件只允许经显式确认的绝对可执行路径、程序摘要、参数、配置环境变量和集群输入组合，禁用交互式插件；组合变化重新确认。测试和每轮采集必须成功读取 `kube-system` Namespace UID 和 Node LIST 首页；保存前者作为该绑定的身份锚点。 |

凭据文件保存在管理员或本机操作者控制的位置；应用只持久化引用，私钥口令及通知密钥放本机系统凭据存储或部署侧受保护文件。不在浏览器响应、URL、任务结果或日志中输出明文。已固定的主机密钥不由后续连接自动替换。连不上时区分 DNS、超时、身份变更、鉴权失败及 RBAC 拒绝；需 VPN 或跳板的目标由操作者提供通路，不通过第三方转发数据。

**SSH 服务器身份。** SSH 握手时服务器提供主机公钥，客户端优先核验绑定已保存的密钥；首次绑定读取运行应用的本机用户的 `~/.ssh/known_hosts` 和 `~/.ssh/known_hosts2`。服务器校验用户的 SSH 登录身份是另一环节。没有可信记录时，登录前返回当前角色、地址和 SHA-256 指纹。操作者从可信来源核对指纹后确认并重新测试；确认票据绑定本次配置及每一跳看到的密钥，票据过期或改参数后须重测。已知主机出现不匹配密钥时返回 `identity_changed`，不能通过普通确认覆盖。成功测试和保存后将确认的主机身份写入绑定，后续采集及维护复用它；不修改这两个本地文件。

**本机私钥路径。** SSH 表单保留可编辑的绝对路径和 [选择文件]。本地 API 打开系统文件选择窗口，只回填选中文件路径；取消保留原值，窗口不可用时仍保留手填方式。选择窗口无参数、需本地会话和同源请求，一次只允许一个窗口，最多等待两分钟。macOS 使用系统对话框，Linux 需要有图形会话及 `zenity` 或 `kdialog`，Windows 使用系统文件对话框。

1. **测试与保存**：测试结果由服务端发放短期凭据，绑定标准化参数和可信身份；保存必须使用同一组合，修改连接参数后重测。缺少防火墙读取权不阻断主机绑定；集群的单项资源缺权在测试结果中点明，不显示成空资源。
2. **编辑**：每条绑定有独立 `target_id`；涉及地址、Context、信任或凭据配置的修改递增 `connection_rev`，并证明仍属同一目标。身份变更按新绑定处理；改显示名不改变身份或采集版本。旧版本的在途采集结果不能写入新版本。
3. **手动关联**：宿主机与 Node 以 `host_id → cluster_id + node_uid` 建立一对一关联；不按名称或 IP 自动配对。Node 删除或同名重建后，原关联待重新选择。
4. **解绑**：在单个本地事务中停用目标、作废旧采集版本、取消排队任务、暂停相关规则，保留历史告警。解绑集群清理节点关联，不影响独立绑定的主机。解绑不自动卸载辅助程序或启停远端服务。运行中的启停或授权维护结束前，解绑和修改连接版本返回冲突；结果待核实时提示远端可能已变更，经确认后可解绑，保留最后操作记录。重绑使用新 ID，不复制操作授权、不自动恢复原规则。
5. **操作身份**：主机与集群绑定只要求只读连接。需要启停时，在「主机管理 → 编辑」单独配置操作凭据引用及允许操作的已采集对象。高权限防火墙维护凭据、服务启停凭据和日常采集凭据不得复用。连接版本变化后重新确认操作授权，细则见 §7.3。

## 3. 轮询、手动采集和调度

设置保存全局 `poll_enabled` 和三组周期：**主机性能与 systemd 默认 60 秒，主机网络默认 300 秒，Kubernetes 资源默认 60 秒**。周期整数单位为秒，V1 可设 10–86,400 秒；保存后重排计划任务。默认轮询开启，可随时关停。防火墙维护和通知投递不属于轮询，关掉轮询不会丢弃已登记的投递。

- 「主机管理」提供采集设置及按目标「立即采集」，机器性能、网络、集群页也可以按当前目标和栏目发起采集，不用开启轮询。触发接口返回任务 ID，界面展示排队、执行中、成功、部分成功、失败或取消。页面普通刷新只重读本地数据。纯手动任务不替代计划采样；手动分项并入到期的计划任务时，保留分项各自的计划或手动来源，每个分项最多计作一次观察。
- 同目标最多一个采集任务执行；已有待执行任务时，同目标请求合并其分项。正在跑且覆盖手动请求时返回该任务；未覆盖的分项最多合并成一轮待执行。客户端退出或休眠错过的计划不补排。在关闭轮询、改周期或解绑时取消尚未开始的不适用计划；已完成的新鲜观察保留。
- 各类目标各用限并发池，初始 SSH 4、Kubernetes 2；手动与自动都有等待时，连续最多发 3 个手动任务后发 1 个自动任务，同类按到期/入队时间排序。每目标最多保留一条合并后的待办，不积压欠采轮次。默认连接 5 秒、SSH 单分项 10 秒、Kubernetes 单请求 5 秒、采集整轮 45 秒；可在高级设置调高整轮超时以适应大集群。超时停止未完成部分并记录失败，不把截断数据发布为完整结果。
- 采集结果的正式字段：目标 ID、连接版本、分项、批次 ID、来源（计划或手动）、设置版本、开始/完成时间、结果、错误类别；成功时另有观察时间。按 `target_id + connection_rev + group + batch_id` 幂等提交。分项失败保留上次完整数据并显示原因；空集合仅由成功完整的采集产生。轮询模式按两倍配置周期标记过期；关闭轮询标记「自动采集已关闭」，每条快照仍显示实际采集来源及观察时间。
- **失联与分项失败分开**：完成的 SSH 探测或 Kubernetes 连接探测失败才计为目标失联；相邻已执行失败轮次之间的计划退避不清空失联计数。客户端休眠、进程重启、排队或任务取消不等价于目标失败；恢复后的探测重新建立连续性。仅防火墙缺权、LIST 后续分页出错等保持分项错误。失败后下次自动探测间隔按正常连接探测周期的 2、4、8 倍递增，且最多在基准周期上增加 300 秒；成功即清零。主机用性能/服务周期与网络周期中较短者作为连接探测基准，集群用集群周期。手动采集不受退避时间限制。

## 4. Linux 采集

普通采集用专用 SSH 账号。到期分项顺序执行固定命令，同一目标的一轮复用已认证的 SSH 连接；不把浏览器字段拼到远端命令，不引入远端解释器依赖。主机基础采集依赖 `/proc`、systemd、GNU `df` 和 iproute2；缺失命令只影响相应分项。远端每个普通采集分项的输出上限默认 4 MiB，超过时不发布部分结果。

| 分项 | 数据源与口径 |
| --- | --- |
| CPU | 读 `/proc/stat` 汇总计数，两点差分；分母含 user、nice、system、idle、iowait、irq、softirq、steal，使用率扣除 idle 和 iowait，不重复计 guest。首次、重启、计数倒退或间隔过长时仅建基线。 |
| 内存 | `/proc/meminfo`，`(MemTotal - MemAvailable) / MemTotal`；缺字段不估算为零。 |
| 磁盘 | GNU `df` 读取本地磁盘挂载点，排除伪文件系统和网络挂载；展示已用和总字节，使用率取 `used / (used + available)`；主机摘要取有效挂载点最大使用率。 |
| 网卡速率 | `/proc/net/dev` 按接口以 RX/TX 字节增量除以实际采样间隔；首次、计数倒退或已知接口重建时重建基线。手动模式需同一启动周期内两次有效样本才能显示速率。 |
| systemd | 合并系统级已安装 unit-file 与已加载 unit 清单，批量读取 `Id`、`LoadState`、`ActiveState`、`SubState`，以规范单元名去重；未实例化模板不当作服务。不读用户级 unit。状态投影和单元启停见 §7.3。 |
| 接口与路由 | `ip -j address show` 读地址、链路、MTU；分别读 IPv4/IPv6 全表路由，保留表、前缀、下一跳、接口和 metric，多路径保留各下一跳。 |
| 端口 | `ss` 分协议、地址族读 TCP 监听与 UDP 本地绑定端点，保存 `protocol + family + address + port`。进程归属尽力读取，缺权限不影响已读取的端口事实。通配地址独立于具体 IP；端口监听不等于远程可达。 |

CPU 和网卡差分要求同一远端 boot ID；网卡同时比较接口名与 ifindex。自动样本的差分窗口为性能周期的两倍，手动为 10 分钟；两类任务分别保留基线，避免手动点击改变自动取样口径。不存在有效基线时，手动采集先建基线并在同轮至少等 1 秒后取第二点；第二点失败才提示需要再次采集。业务告警见第 8 节；失败轮次不退回使用旧快照。

## 5. 防火墙只读采集和辅助程序管理

### 5.1 规则来源

Linux 读取器是无参数、无常驻进程的 Go 辅助程序，默认构建 `linux/amd64`、`linux/arm64`。安装时登记可用后端的系统路径，执行前确认真实路径由 root 控制、不可由采集用户写入；使用固定参数、最小环境及 `LC_ALL=C`，不接收运行时命令或环境注入。按后端分别返回版本化结果 `{backend,status,observed_at,format,payload,error_code}`；每项限时、限输出。普通采集账号以 `sudo -n -- <FIREWALL_READER_PATH>` 调用，中心解析后再存盘。

| 读取项 | 数据读取与呈现 |
| --- | --- |
| UFW | `ufw status verbose` 提供启用状态、默认策略和 UFW 自身管理的规则。作为管理视图，不把这些规则重复加到内核数据；UFW 未启用不意味着其他防火墙为空。 |
| nftables | `nft -j list ruleset` 读取 nftables 表、链、匹配和动作，包括使用 nf_tables 的 iptables 兼容规则。不另读通用 `iptables-save` 来重复计数。 |
| iptables-legacy | 优先用 `iptables-legacy-save` 和 `ip6tables-legacy-save` 读取已加载的 IPv4/IPv6 规则；只有系统通用入口明确报告后端为 legacy 时才使用对应的 `iptables-save` 或 `ip6tables-save`。两种方式均不指定表，不回退到 iptables-nft。保存链策略及无法拆解的匹配和动作文本。 |

UFW 行额外保留方向、来源和操作。界面分别展示三种来源及其读取状态，不尝试推演一条流量能否通过所有规则。未安装工具显示「未检测到工具」；无权限显示「不可读」；后端明确不受支持才显示「不支持」；超时、不能解析和输出超限为失败；只有完整读取成功才可能显示「无规则」。不能结构化但完整读取的规则保留原始表达式，不作空条件。防火墙失败不影响接口、路由和端口，也不算整机失联。

### 5.2 自动安装和卸载

| 阶段 | 安装 | 卸载 |
| --- | --- | --- |
| 发起 | 主机管理 → 主机行 [安装授权]。显示目标指纹、采集账号、辅助程序版本及将更改的文件，确认后启动独立维护任务 | 同一主机行显示 [卸载授权]。卸载停止该采集账号调用读取器，不清空或调整防火墙；网络详情仅显示当前读取状态和授权说明 |
| 管理员连接 | 单独选择已授权的管理员 SSH 凭据，校验与已绑定主机一致；要求具备本次维护需要的非交互提权，否则转入 5.3 节。定时和手动采集均不使用管理员凭据 | 同左，仅允许卸载本产品登记的版本、路径和账号；清单不存在但发现同名文件时不接管 |
| 文件变更 | 只修改本产品的读取器、sudoers drop-in 和版本清单。使用 root 管有的暂存目录，校验发行包 SHA-256；先检验文件所有权、现有 sudo 配置和新 drop-in 语法，再装读取器及清单，最后原子发布授权 | 预先核对清单和文件；先移除产品的 sudoers drop-in，再移除清单对应的读取器和清单。发现手工改过的文件不擅自删，列出需管理员处理的路径 |
| 确认 | 重新用普通采集凭据调用固定读取器，能收到正确版本的协议响应后显示「已安装」，随后刷新各后端。单个后端无规则或未安装不否定读取器已安装 | 同样用普通采集账号验证固定调用已被拒绝或程序不存在；远端记录与验证一致才显示「已卸载」 |

读取器、sudoers 配置与版本清单使用[维护脚本](../../internal/firewall/maintain.sh)定义的固定路径，以便新版继续识别和卸载已安装的授权。一台宿主机 V1 只维护一套读取器和一个已登记的采集账号；同款其它客户端使用同账号时共享该读取器。授权为精确路径、`NOPASSWD: NOSETENV:`、`""` 匹配无参数调用；不向采集用户授予安装、任意命令或管理员 shell。发行包内嵌按目标架构选取的自包含维护脚本，脚本带读取器字节和版本；自动路径由已有管理员权限建立 root 私有暂存目录，校验文件后从该目录执行，不提权执行普通账号可写路径内的脚本。

维护按主机串行，用 root 管有路径内的锁防止两个客户端同时修改。重复执行同目标同版本安装或已完成卸载会验证现状后返回；更新保存受管文件的旧版本，安装校验失败恢复旧文件，首次安装失败撤销新增授权及文件。若 SSH 中断、进程退出或权限变化导致远端结果不明，显示「待核实」；重新连接后按清单、文件和普通账号探测核对，不假报回滚成功。卸载中断若已撤授权优先保持撤权，重试清理残留。未确认变化的远端不根据本地任务记录判断已安装或已删除。

### 5.3 无自动管理员权限

通过已绑定的普通 SSH 用户将同一版本的维护脚本上传至当前账号私有的暂存目录（权限 0700，脚本 0600），先用 SFTP，失败时用固定 SSH 上传流；不得执行。若两种上传均失败，显示失败原因并保留同一发行脚本的本地导出入口。上传成功显示「待管理员操作」、路径和 SHA-256，给出这一台机器对应的命令。管理员在目标主机的 root shell 中执行；摘要从可信本地客户端或发行物取得，不读暂存目录提供的摘要。以下为客户端生成命令的格式，非仓库内已存在的脚本：

```sh
set -eu
collector='<COLLECTOR_USER>'
uploaded='<STAGED_SCRIPT>'
expected_sha256='<SHA256_FROM_TRUSTED_CLIENT>'
action='<install-or-uninstall>'
root_stage="$(mktemp -d /var/tmp/imon-admin.XXXXXXXX)"
trap 'rm -f -- "$root_stage/firewall-maintain.sh"; rmdir -- "$root_stage"' EXIT
runuser -u "$collector" -- cat -- "$uploaded" > "$root_stage/firewall-maintain.sh"
printf '%s  %s\n' "$expected_sha256" "$root_stage/firewall-maintain.sh" | sha256sum -c -
/bin/sh "$root_stage/firewall-maintain.sh" "$action" --collector "$collector"
```

脚本执行前校验调用者是 root、动作和账号格式合法、账号在本机存在，且路径和现存文件均满足上节约束。管理员完成后在面板点「重新检测」：普通账号读到有效协议可确认已安装，但读取失败不能单独证明已卸载；需要确认卸载时选择已授权的管理员凭据复查受管文件。确认与原任务动作一致后更新待办记录，客户端清理自己创建的暂存文件。仍待核实的状态不显示规则为「无规则」。

## 6. Kubernetes 采集

不依赖 K3s、集群内 Agent 或 Metrics Server。只读权限用专用身份授予；使用集群级 RBAC 才能读取所有命名空间。连接必需权限是核心组 `get namespaces`（通过 `resourceNames` 限定 `kube-system`）和 `list nodes`；其余 `list` 按监控项授予：核心组的 Namespaces、Pods、Services，`apps` 的 Deployments，`discovery.k8s.io` 的 EndpointSlices。采集身份不授予 Secret、日志或集群写入权限；Deployment 启停使用 §7.3 的独立操作身份。对首版不具备 `discovery.k8s.io/v1` 的集群明确提示后端计数不支持，不回退读取旧资源。

各类型独立按 200 个对象一页 LIST；以解压后的响应大小计，每页默认不超过 8 MiB。收到 `410 ResourceExpired` 丢弃该类型未完成结果，时限内从第一页重试一次。采集器分页提取展示、关联和判定所需字段，在内存中汇集该类型的结果；完整读取后，存储层每批最多写入 200 行到不可见的候选代，全部写入成功才发布。请求超限、超时或写入失败时丢弃候选代，保留旧值并标记错误。分页限制单次响应大小，不限制一个资源类型的总内存占用。不把不同类型同轮采集视为原子远端时刻；组合统计只使用同轮完整输入。

| 资源 | 存储和状态判定 |
| --- | --- |
| Namespace | UID、名称、阶段；部署、Pod、Service 数分别从同轮完整资源统计，分项失败返回未知而非 0。 |
| Node | UID、名称及 Ready 条件的 True、False、Unknown；无条件显示未知。按 Node UID 查找手动关联的宿主机。 |
| Deployment | UID、命名空间、名称、期望及就绪副本。只有 `observedGeneration >= generation` 才判定是否副本不足；否则显示「更新中」。期望与就绪均为 0 时标记「已缩容」；缩容过程中仍展示实际副本，不报副本不足。 |
| Pod | UID、命名空间、名称、阶段、Ready 条件、所在节点、是否删除中。集群连接摘要「异常 Pod」计未在删除中的 Failed、Unknown 和 Running 且 Ready=False；Pending、Succeeded 和缺少 Ready 的 Pod 另显示原始状态，不计入该摘要。 |
| Service | UID、命名空间、名称、类型、协议和端口。ExternalName 和无 selector 的 Service 的就绪后端数不适用；受支持的 Service 由下述方式计算。 |

Service 后端按命名空间和 EndpointSlice 的 `kubernetes.io/service-name` 标签关联；有 Service 所有者引用时还匹配 UID，避免同名重建时计入旧后端。计入就绪且未终止的端点，缺少 `ready` 按 API 语义视为就绪；若 Service 设置 `publishNotReadyAddresses`，以明确的 `serving=true` 和未终止为准，缺少 serving 且会影响计数则返回未知。优先按 Pod UID 跨切片及地址族去重；无 Pod UID 时按地址类型和地址去重。只有完整读取并确认不存在合格后端才为 0；读取失败显示未知。后端数不代表网络可达。

## 7. 存储、接口和页面

### 7.1 SQLite 契约

使用 WAL、单写入协程、短事务和分页读。对象身份固定：systemd 按目标与单元名，磁盘按目标与挂载点，网卡按目标与接口名，端口按目标与完整绑定元组，Kubernetes 按集群目标、类型及 UID。接口改名或同名 Kubernetes 对象重建不自动迁移告警。所有持久时间为 UTC 毫秒，界面按客户端时区展示。

| 表 | 主键和约束 |
| --- | --- |
| `targets`、`node_links` | `target_id` 持久化名称、类型、连接引用、版本和启用状态；节点关联对 `host_id` 和 `(cluster_id, node_uid)` 各设唯一约束。 |
| `sampling_settings`、`collection_jobs`、`target_probe` | 本地轮询配置；统一保存采集、启停和防火墙任务；目标最近连接探测及失联计数。重启取消遗留采集或未开始的任务；遗留执行中的远端写入任务标为待核实。 |
| `group_state`、`snapshot_batches`、`snapshot_rows` | 按目标、连接版本、分项存最近尝试和成功指针；对象按该键、候选代和对象键存行。候选代不可见，确认成功后切换指针；分项失败仍可读上次快照及其时间。旧代及中断候选代批量清理。 |
| `performance_samples`、`sampling_baselines` | 历史样本按目标、连接版本、指标、维度和批次区分；自动与手动差分基线分开。有效历史固定保留 7 天，查询按序列最多分 600 桶并返回有数据桶的均值及峰值；前端对超出采样间隔容许值的空档断开曲线，不填成零。 |
| `alert_rules`、`rule_state`、`alert_events` | 规则及版本、来源选择器、条件和渠道；每规则最多一个活动事件；事件快照保存规则与对象名称、级别、条件、数据来源、初始值、最新值、触发与恢复时间。事件按 `(triggered_at,event_id)` 倒序索引，另存 `panel_revision` 和 `panel_read_revision`，初始均为 0。 |
| `notification_settings`、`notification_targets`、`deliveries` | 三个全局开关、外部目标配置、各阶段投递结果。按事件、阶段、渠道及目的地址去重；已入队的配置不可变。面板通知无需单独收件箱。 |
| `firewall_maintenance` | 以任务 ID 关联通用任务记录，登记目标、连接版本、动作、暂存路径、脚本摘要和目标架构；核实结果通过对应任务查询。 |
| `service_authorizations`、`service_action_details`、`deployment_resume` | 操作授权绑定目标、连接版本及对象键；任务详情保留动作、前置状态及发送/确认标记，通用任务记录保存结果；恢复副本按集群目标、连接版本和 Deployment UID 隔离，不能跨同名重建复用。 |

发布快照、写指标、评估受影响的规则及登记事件和投递为同一事务；写入前再次验证连接版本，禁止旧任务污染当前绑定。磁盘写失败时标记本地存储错误，不承诺刷新或告警成功。告警历史不随解绑删除；临时任务记录保留 7 天，正在运行、待发送或结果待核实记录不因保留期限清理。采用 SQLite 在线备份生成一致副本；恢复时停止进程后替换状态库，凭据另行恢复。迁移按版本单向执行，开始前备份，失败不得继续用半迁移库采集。

### 7.2 API 和界面

界面一级导航为「服务」「主机管理」「网络」「告警」，侧栏底部显示版本号。启动打开服务首页。主机管理的主机 [查看] 打开机器性能，集群 [查看] 打开集群详情；一级「网络」先选主机，机器性能也可直接查看同一主机的网络详情。告警默认打开事件列表，另有规则和通知渠道标签；事件详情是独立视图。

由单页外壳处理前进、后退以及列表到详情的普通导航；菜单、标签和详情按需从本地 API 异步加载，仅更换内容区域。快速切换时，迟到响应不得覆盖当前页面。共用页首操作栏、表单网格和输入控件高度；窄视窗按行换行，不挤压按钮及输入。面板列表支持稳定排序与游标分页（默认 50、最多 200 条）。错误 JSON 使用 `{code,message,retryable}`。常见状态为 400（参数）、401（本地会话）、403（功能未授权）、404（目标或对象已不存在）、409（身份、版本或任务冲突）、503（本地存储不可用）。排队任务返回 202 和 `job_id`；后台远端失败进入任务或分项结果。

| 界面 | API 与主要交互 |
| --- | --- |
| 服务首页 | `GET /api/v1/services` 统一列出 systemd 和 Deployment；筛选参数 `source`、`host_id`、`cluster_id`、`namespace`、`state`、`q`。`GET /api/v1/services/{id}` 返回对象键、位置、状态、采集信息和可用操作；Deployment 同时返回 `ready`、`desired`。`POST /api/v1/services/{id}/actions` 发起启停；[创建告警] 带入当前对象及服务状态监控项。 |

| SSH 测试与选取私钥 | 首次连接时测试返回 409，`code=host_key_confirmation_required`，`details` 包含 `role`（`jump` 或 `target`）、`address`、`fingerprint`、`confirmation_token`。确认后带 `ssh_confirmation_token` 重试；后续跳数使用最后收到的票据。通过后保存绑定使用 `test_token`。`POST /api/v1/local/file-picker` 无请求体；选中返回 200 和 `{path}`，取消返回 204；窗口占用、打不开和超时分别返回 409、503、504。 |

| 机器性能 | `GET /api/v1/hosts/{id}/metrics?from=&to=` 返回 CPU、内存、各挂载点、各网卡最近有效值和历史趋势。磁盘行支持预填挂载点和使用率创建规则。 |

页面分别显示对象健康和采集状态。首采显示等待，已知旧值保留时间及失败原因，成功空才为空列表。手动任务完成后只刷新对应分项；隐藏的页面不轮询 UI。用户在告警详情仍可看到已解绑目标的名称快照，跳转不会指向同名新对象。

主机列表摘要取最新有效的 CPU、内存百分比和挂载点最大使用率；集群列表显示就绪节点数／节点总数和 §6 定义的异常 Pod 数。缺少完整输入时显示 `--`，不显示 0；沿用旧值时保留采集时间及失败原因。

### 7.3 服务状态与授权启停

| 统一状态 | systemd | Deployment |
| --- | --- | --- |
| `running` 运行中 | `LoadState=loaded`、`ActiveState=active` | 当前 generation 已观察、期望大于 0 且就绪副本达到期望 |
| `failed` 失败 | `ActiveState=failed` | 当前 generation 已观察、期望大于 0、未达到就绪，且有明确失败条件（`ProgressDeadlineExceeded` 或 `ReplicaFailure=True`） |
| `stopped` 停止 | `LoadState=loaded`、`ActiveState=inactive` | 当前 generation 已观察，且期望和实际副本均为 0 |
| `starting` 启动中 | `ActiveState=activating` | 实测期望由 0 增至正数、尚未达标且未观测到当前 generation 的明确失败；普通滚动更新不自动标为启动中 |

按明确失败、完成态、启动中的顺序匹配。不能归类时 `state=null`，状态列显示 `--` 并单独说明「等待采集」「状态暂不可判定」「停止任务处理中」等；过期快照保留旧状态及时间，不作为启停依据。正副本但部分就绪且无失败条件的 Deployment 在集群详情展示真实副本；服务首页不把它硬映射为失败。服务启停规则也只消费有结论的状态，不以连接失败代替服务失败。

- **请求与授权。** `POST /api/v1/services/{id}/actions` 接收 `{action,connection_rev,expected_state,expected_desired?,replicas?,confirm_unknown?}`；`action` 只允许 `start`、`stop`。`expected_state` 和 Deployment 必填的 `expected_desired` 取自确认页，用于本地快照及远端前置校验；不一致则要求刷新后重新确认。`replicas` 在 Deployment 没有可用恢复记录时作为启动必填的正整数（int32），其它情形不得指定。编辑授权提交 `{connection_rev,credential_ref,object_ids,external_manager_checked?}`，凭据为独立 SSH 或 kubeconfig/Context 引用；`object_ids` 必须属于当前绑定，Kubernetes 还须确认没有外部副本管理。默认无授权。界面确认对象、动作及副本数；后端不接受浏览器传递任意命令、单元名或集群路径。
- **systemd。** 管理员通过 sudoers 为独立 SSH 操作账号授权精确的固定 `systemctl` 路径和 `start -- 单元名`、`stop -- 单元名` 参数，中心以 `sudo -n` 执行。无通配、不改 enable/disable、unit 文件或其他策略；不借用防火墙 sudo 规则。V1 启停只接受匹配 `[A-Za-z0-9_][A-Za-z0-9_.@-]*\.service` 的已采集规范单元，发送前复查同一 `Id`、`LoadState` 和 `ActiveState`。依赖、socket/timer 激活等能影响实际状态，确认后以读回结果为准，不反复发命令维持状态。
- **Deployment。** 操作身份只获得指定命名空间内、指定工作负载的 `deployments/scale` `get/update`，以及复核所需的该 Deployment `get`、命名空间 HPA `list` 与 API 身份锚点读取。只允许管理员确认无外部副本管理的 Deployment。操作前确认身份锚点、当前工作负载及完整 HPA 列表；有匹配 HPA、已知外部管理、paused、删除中或无法确认时拒绝，不修改控制器策略。读取 Scale 后要求 UID 和 `resourceVersion` 与刚读到的 Deployment 一致；保留版本字段调用 Scale `PUT`。版本不一致或 409 不自动重试；不改模板、不直接删除 Pod，也不改 Service。集群外部控制并非能全自动识别，启用授权时须由集群管理员确认管理归属。
- **停止和恢复。** 停止将当前正副本数、UID 和连接版本写入待确认的本地任务，再尝试缩容至 0；只有确认同 UID 的 Scale 已写入并读回 0 才建立可用恢复记录。启动仅对期望为 0 的 Deployment 增加副本，优先恢复记录，无记录请求用户输入。读回目标正副本后清除对应恢复记录。已要求正副本但失败的 Deployment 仍显示 [启动]，按钮禁用并提示去集群详情查看原因；重复设置当前副本数不是重启或修复，不显示虚假启动成功。
- **任务和核实。** 每个对象同一时刻只执行一个启停任务；在途请求内容相同返回同任务，反向动作或授权变更冲突返回 409。写前持久化意图，再校验绑定版本与授权。systemd 命令明确成功且读回目标状态才记成功；Deployment 写入并读回 Scale 目标值后任务成功，副本达标另在 `GET /api/v1/jobs/{id}` 的 `results.convergence` 显示（`pending`、`confirmed`、`not_confirmed`、`workload_failed`）。待副本收敛时每 5 秒左右只读复查一次，累计最多 60 秒；单对象复查只更新任务状态，不作为完整快照或规则样本。启停确认写入后提交正常手动分项采集，不依赖轮询开关；复查达标后再提交刷新。写操作未收到明确答复时标「待核实」；重启也不自动重发或认定旧写入成功。界面要求操作者先核实当前对象、刷新状态并确认，再以 `confirm_unknown:true` 重试。未授权启停仍可监控并创建告警。

## 8. 告警和通知

### 8.1 规则与状态机

每条规则绑定一类对象及监控项，配置比较符（数值阈值或状态匹配）、严重级别、持续秒数或连续采样次数（二选一）、启停状态，以及三渠道独立开关和所需目的地址。

| 数据源 | 可配置项 |
| --- | --- |
| 主机性能 | CPU、内存、磁盘使用率，磁盘容量，指定接口收发速率。单位与性能页一致。 |
| systemd | 指定单元的统一服务状态。缺失单元不当作停止。 |
| 端口 | 指定主机、协议、地址族、绑定地址及端口的存在/缺失。只有该协议和地址族的完整快照能证明未监听；进程字段缺权不影响条件。 |
| Kubernetes | Node Ready；Deployment 的统一服务状态或非负的期望与就绪副本差（观察到当前版本才评估副本差）；Pod 阶段或 Ready。零期望副本时不评估副本差，停止状态仍可作为独立条件。Service 后端用于展示，不作为 V1 工作负载告警源。 |
| 采集失联 | 目标的连接探测结果（第 3 节），不读取旧快照来推定。 |

- 新鲜、有结论的异常样本进入待触发；达到条件后建一条活动事件。持续条件以第一条计划异常样本计时，后续计划异常样本达到门槛才触发；连续次数只累积不同有效批次。已活动的异常只更新最新观测，不重复通知。新鲜且确认条件不再成立才恢复；未知、返回旧数据和对象消失均不判恢复。
- **轮询开启时**，多样本次数、非零持续时间由计划采集推进。手动样本能触发单次规则，能确认恢复；明确正常或未知的手动结果也可中断待触发连续性，但不能替代后续计划异常样本。**轮询关闭时**，单次规则及以次数为条件的规则只消费手动样本；次数累计表示连续有效的手动观察，间隔超过两倍相关配置周期时重置。非零持续时间规则保留配置、不新触发，界面显示「需开启轮询」；已有活动事件仍可用新鲜正常样本确认恢复。持续时间为 0 等同连续 1 次。切换模式或调整相关周期重置待触发，不结束已有事件。计划轮次推进以该轮入队时的设置版本为准，设置已变更的在途轮次只可写快照，不推进规则。
- 分项失败、观测失鲜或非预期采集间隙重置尚未触发的业务条件。失联规则只消费实际完成的失败或成功探测；正常退避不打断其失败连续性。中心进程重启、休眠恢复或过载造成的计划观察中断，则重置待触发连续性但保留活动事件。未执行的任务不被记为失败。
- 停用规则、解绑或编辑目标/条件/连接版本时，终止原判断。活动事件保存为「监控停止」或「配置变更」，不发恢复通知；只改名称、级别或通知开关不重置。连接正常但目标对象不存在时，活动事件附「暂不可评估」，不误报恢复；按 UID 绑定的 Pod、节点和部署需人工改绑同名新对象。

事件列表默认查询所有状态，按触发时间倒序，同毫秒用事件 ID 倒序作稳定分页键。「活动」「已恢复」分别只筛选 `active`、`recovered`；「监控停止」「配置变更」不混入已恢复。「未读」独立于事件状态。面板列显示未读、已读或 `--`（从未投递）。详情展示规则和对象当时的名称、触发条件及级别、最新值与观察时间、触发与恢复时间、数据来源及各阶段投递结果。返回保留列表筛选；来源失效时保留快照并禁用跳转，不跳向同名对象。

### 8.2 投递

面板通知、Telegram、邮箱都有全局启用开关，默认仅开启面板；规则独立选择三个渠道。每次触发或恢复时，在事件事务内分别记录当时的选择及开关结果，只有两层都启用才投递。其余在详情显示「规则未选中」或「未启用」（两者均不满足时显示「未启用」）；两层全关仍保留事件。开关只作用于之后产生的阶段，不补发旧事件、撤销已登记的外部投递或清空既有未读。

- **面板**：某个事件阶段向面板投递时，在事件事务内将该事件 `panel_revision` 加 1，阶段显示「已投递」。`panel_revision > panel_read_revision` 代表未读。打开事件详情后，前端提交看到的 `panel_revision`；后端以 `max(panel_read_revision,through_revision)` 更新，拒绝负数及超出当前 `panel_revision` 的值。重复请求不额外减计数，后来到达的恢复通知保持未读。侧栏和事件列表共用全库未读事件数；翻页、筛选和查看未投递事件不改变未读数。

- **Telegram**：本地客户端通过 HTTPS 访问 Bot API，使用已配置机器人和会话，支持所选本机 HTTP CONNECT 代理或直连。没有可达路径时报告测试或投递失败；不要求新增中转服务。日志中不打印含令牌的 URL。
- **邮箱**：本地客户端连接配置的 SMTP 服务或现有中继，使用校验证书的隐式 TLS 或强制 STARTTLS。保存发件人、收件人及凭据引用，每个收件人单独记录结果。远端接受表示「已受理」，不表示送达收件箱。
- **测试**：从通知设置或规则编辑器显式测试所选 Telegram 或邮箱目的地，展示结果，不创建业务事件、不增加业务未读数；即使关闭自动投递，也可测试已配置的目的地。面板渠道测试仅在当前表单展示测试结果。通知出站受限时，配置相应代理或现有邮件中继；只影响该渠道，不切换采集架构。

投递记录在入队时固定事件阶段、消息、地址、传输参数和凭据引用；后续编辑不改变已有投递目的地。独立的 2 槽发送池在短事务内认领，单次发送超时 15 秒。仅对明确未受理的临时错误重试，默认延迟 30 秒、120 秒，每次不早于对端要求；凭据错误等永久错误直接失败。对端可能已受理但回执丢失，或进程重启发现遗留「发送中」，标「结果未知」而不自动重发。同事件同渠道同地址先将触发处理到终态再处理恢复；投递结果与事件生命周期独立。

## 9. 构建交付与验证

| 组成 | 预期工程落点及交付内容 |
| --- | --- |
| 客户端 | `cmd/imon` 负责启动和数据命令；`internal/{appdata,httpapi,store,control,collector,alert,update}` 实现数据目录、API、调度、采集、告警投递和更新；`web/` 为嵌入式面板。`packaging/release/build.sh` 分别打包 Windows、macOS、Linux 的 amd64 和 arm64，并生成 `SHA256SUMS`。启动无需额外数据库或前端运行时。 |
| 远端读取器与维护入口 | `cmd/imon-firewall` 为一次性 Linux 读取器；`internal/firewall/` 管理维护脚本和嵌入清单。发布构建嵌入 Linux amd64、arm64 的维护包；普通本机构建不含维护包。远端安装卸载只由第 5 节流程显式触发。 |
| 联调环境 | Linux+systemd 可测账号、隔离服务及其操作账号，三种防火墙测试环境与独立管理员账号，Kubernetes 专用只读身份及隔离 Deployment 的 Scale 操作身份，可控 Telegram/SMTP 测试端。测试使用占位或生成值，不提交真实凭据、主机名或结果。 |

开发顺序和依赖见 [开发计划](../plans/01-v1-technical-solution.md#开发顺序)。两个只读适配器可分别贯通；远端写入在单独授权的隔离目标验证。交付时至少应验证以下可复现行为：

1. 不部署专用服务器，从本地程序完成绑定、性能/服务/网络读取、集群筛选、节点关联和解绑；关闭轮询仍能手动采集。压测绑定规模不靠拒绝新增达标，记录实际吞吐、排队时间、中心 RSS/CPU、远端耗时和 SQLite 增长；结果发布为测试环境下的测量值，而不是无限吞吐承诺。
2. 在分别使用 UFW、nftables、iptables-legacy 及混用的环境覆盖后端识别、授权缺失、安装重试、无管理员权限上传、卸载和中途断链，检查不修改任何防火墙规则，并验证普通采集账号没有维护权限。
3. 宿主机验证单单元启停且不改开机策略；集群验证独立 Deployment 从 2 → 0 → 2、同名新 UID 和版本冲突不误写，开启 HPA 或撤销写权限后仍可只读。权限缺失或归属不明时，保留预检失败证据，相应真实启停保持待验证，列表和报警不受影响。
4. 用固定样本验证过期、目标消失、重复批次、触发去重、恢复、失联退避、手动模式和中心端重启。验证告警默认事件列表、详情返回、全关仍记事件，恢复投递不能被旧详情误清。通过可控通知端覆盖发送失败和回执未知，用测试通知核实实际出口。
5. 验证导航切换无整页重载、窄视窗表单对齐、首次 SSH 连接确认和密钥变更拦截。验证解包后内嵌版本、启动只检查一次、更新源未配置、平台包缺失及摘要不匹配；用隔离发布包验证自动重启、会话恢复、新程序启动失败后的程序与 SQLite 回退。

## 10. 版本更新和本地数据

- **版本来源。** 构建时可预设公开 GitHub 仓库 `<OWNER>/<REPO>`；启动参数 `--release-repo` 可以指定仓库。不使用 Token，不执行 `git pull`，不执行仓库源码。`--version` 和侧栏底部显示当前构建版本。
- **检查。** 应用启动后首次打开面板时自动获取一次仓库最新正式 Release，仅识别 `vMAJOR.MINOR.PATCH`，忽略草稿及预发布。路由切换、展开气泡和同进程再次打开面板不再检查。按当前系统和架构匹配 `imon-web_<GOOS>_<GOARCH>.tar.gz`，Windows 用 `.zip`。发现新版本时侧栏版本号显示红点；气泡显示发布信息及可信的 GitHub 发布页链接。无仓库、已是最新、缺平台包或无有效 SHA-256 时不进行自动安装。
- **下载和校验。** 点击 [更新] 提交展示的标签和 SHA-256；中心复核 Release，版本、摘要或可用性改变时拒绝继续。发布包最大 128 MiB，下载过程中校验大小和 SHA-256，校验成功后才写入成品。解包只提取匹配的客户端可执行文件，不用发行包内脚本或文件覆盖数据目录。
- **自动安装。** 可原地替换的 macOS 和 Linux 安装显示 [更新]；Windows 或不支持替换的位置保留发布页链接。安装暂停采集并备份 SQLite，保留旧程序；新版本沿用原启动参数、数据目录和回环端口。浏览器在同一个已认证会话等待运行确认，新版本启动失败时恢复旧程序，必要时还原更新前数据库。手动备份与恢复继续使用 `--backup <BACKUP_FILE>` 和 `--restore <BACKUP_FILE>`，不包含外部凭据文件。具体操作见 [安装、备份与恢复](../guides/backup-and-restore.md)。
